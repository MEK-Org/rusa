# PR #868: handle-granted Events appearance

The live dashboard Events row previously showed the pairwise role, here
`reviewer for your patch`. New grants after #868 have no role detail, so that
line disappears. The timestamp, kind chip and target handle remain. Removing
the line also reduces the row height. These captures cover that exact effect
at desktop and phone widths, for Matt's appearance review.

## Sources and capture boundary

- Before server: staging `19209da52541d76f139518b856cd427df6209e4f`.
- After server and dashboard renderer: PR #868 head
  `842b3d3c8f61467d773c6277324e4a076c016184`.
- The entire `packages/rusa/flutter_dashboard` tracked tree is identical between
  those two source commits (`git diff --name-only <base> <head> --
  packages/rusa/flutter_dashboard` prints nothing). The data change causes the
  visible difference; the same real widget is therefore used for both pages.
- Each server capture calls the real `ActorMesh.grantHandle`, records into a
  migrated in-memory SQLite `mesh_events` table, and queries
  `MeshEventRepository.listEventsByActors`, the repository path used by the
  dashboard `/api/mesh/events` route. No HTTP transport or live database is used.
- Both captures use the pre-change introduce call shape `{id, role}`. At the
  after head the runtime strip makes this equivalent to the new role-free tool
  call. The actual tool now rejects the removed `role` argument.
- The fixtures are verbatim captured JSON. Ignoring random event IDs, the only
  difference is `handle_granted.detail`: a role string before, `null` after.
- Actor IDs, charters, titles, handles, timestamps and avatars are synthetic.
  Root's displayed handle `steady-owl` is a harness label. The avatars are
  generated by the existing screenshot helper. There is no production data.
- The real `DashboardBody` is navigated to Actors → selected holder → Events Log.
  The harness asserts that the role text is present before and absent after,
  and that the event kind and target handle are displayed in both.
- Images are captured at 2× DPR: wide PNG 2720×1280; phone PNG 780×1688.
  Flutter 3.41.5 / framework `2c9eb20739`, Dart 3.11.3. Fonts and icons use the
  existing headless screenshot helper. Its Roboto-only monospace mapping leaves
  the peer-arrow glyph as a missing-glyph box in both states; this is a harness
  font limitation shared by both captures, not a change to the widget.
